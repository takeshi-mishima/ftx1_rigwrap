# ftx1_rigwrap Ver.2.0

八重洲無線 FTX-1 用の rigctld（Hamlib）プロキシです。WSJT-X などの rigctld クライアントと rigctld の間に入り、CAT 制御の向き先（MAIN / SUB）をポートごとに振り分けます。WSJT-X を2つ起動してデュアルバンド受信をするとき、#1 を MAIN、#2 を SUB の担当に固定できます（既定）。

あわせて、FTX-1 の CAT で起きやすい次の問題を補正します。

- 制御先がメモリーチャンネルなどのとき、WSJT-X のバンド切替（周波数設定）が無線機に拒否されるのに、成功（RPRT 0）が返ってしまう問題
- CAT で DATA-U / DATA-L にすると、ナローが ON になってしまう問題

WSJT-X #1/#2 に音声を届ける ftx1_audio_swap（fixed モード）と組み合わせて使います。

## 構成

```
WSJT-X #1 ── 127.0.0.1:4535 [main] ─┐
WSJT-X #2 ── 127.0.0.1:4536 [sub]  ─┤ ftx1_rigwrap ──► rigctld :4534 ── COM ── FTX-1
                                    │  （制御用の接続を1本共有）
ftx1_tray / ftx1_audio_swap ─────► rigctld :4534（直結のまま）
```

- rigctld は、ラッパーとは別に起動します。ラッパーはクライアントが接続してきたときに rigctld へつなぐので、起動の順番は問いません。
- ラッパー経由にするのは WSJT-X #1・#2 だけです。ほかのツール（ftx1_tray、ftx1_audio_swap）は rigctld に直結のままで、ラッパーを経由させる必要はありません。

## 待ち受けポートとモード（--listen）

ポートごとに、制御先のモードを指定します（`--listen ポート:モード`、複数指定できます）。

| モード   | 制御先             | 使い方                          |
| -------- | ------------------ | ------------------------------- |
| main     | 常に MAIN          | WSJT-X #1（既定：4535）         |
| sub      | 常に SUB           | WSJT-X #2（既定：4536）         |
| follow   | 操作バンド（VS）   | 操作バンドに追従する WSJT-X     |
| opposite | 操作バンドの反対側 | 非操作バンド側を受信する WSJT-X |

既定は `--listen 4535:main --listen 4536:sub` です。#1 を操作バンドに追従させ、#2 をその反対側にしたいときは、`--listen 4535:follow --listen 4536:opposite` を指定します。この場合、ftx1_audio_swap は `--mode follow` にしてください。

## コマンドの扱い

`follow` はクライアントのコマンドをほぼそのまま rigctld へ中継します（周波数・モードの設定だけ補正します）。`main` / `sub` / `opposite`（以下 routed）は、制御先を固定して中継するため、次のコマンドは扱いが変わります。

| コマンド                                              | follow           | routed（main / sub / opposite）                                       |
| ----------------------------------------------------- | ---------------- | --------------------------------------------------------------------- |
| `F`（周波数設定）、`M`（モード設定）                  | 補正してから実行 | 同左（制御先を指定して実行）                                          |
| `T`（送信 / 受信の切替）                              | そのまま中継     | 制御先が操作バンドのときだけ実行。操作バンドでなければ実行せず RPRT 0 |
| `V`（VFO 切替）                                       | そのまま中継     | 実行せず RPRT 0（操作バンドが変わらないようにする）                   |
| `S`（スプリット）                                     | そのまま中継     | OFF は実行せず RPRT 0、ON は RPRT -9（拒否）                          |
| `I` `X` `K`（スプリットの周波数・モード）             | そのまま中継     | RPRT -11（使用不可）                                                  |
| `\set_vfo_opt`                                        | そのまま中継     | 実行せず RPRT 0                                                       |
| `\chk_vfo`                                            | ラッパーが答える | ラッパーが答える（常に 0）                                            |
| そのほかの VFO を取るコマンド（`f` `m` `t` `s` など） | そのまま中継     | コマンド名の直後に制御先（`Main` / `Sub`）を入れて中継                |

## 必要なもの

- Windows 10 / 11
- FTX-1（CAT 動作には MAIN ファームウェア Ver.1.08 以上が必要です）
- Python 3.8 以上（標準ライブラリのみ。python / pythonw に PATH が通っていること）
- Hamlib の rigctld が FTX-1 に接続して起動していること（既定 127.0.0.1:4534）。
  Hamlib は 4.7.3 以上を推奨します（2026年9月時点では、開発版の 4.7.3~rc を https://hamlib.sourceforge.net/snapshots-4.7/ から入手できます）。
- WSJT-X を2つ起動する場合は、ftx1_audio_swap と Equalizer APO（音声の L/R の入れ替え用）も必要です。

rigctld の起動例（COM ポート、TCP ポートは環境に合わせてください）:

```
rigctld -m 1051 -r COM5 -s 38400 -t 4534
```

FTX-1 のモデル番号は 1051 です。COM ポートは Enhanced COM Port（CAT-1）を指定します。

## 使い方

### 動作確認

rigctld を起動した状態で、コンソールからラッパーを起動します:

```
python ftx1_rigwrap.py
```

※ `pythonw` ではなく `python` で実行してください（pythonw では画面に何も表示されません。ログファイルには記録されます）。

正常なら次の例のように表示されます:

```
2026-10-09 00:20:01,234 INFO ftx1_rigwrap 2.0 起動 rigctld=127.0.0.1:4534
2026-10-09 00:20:01,235 INFO 待ち受け 127.0.0.1:4535 [main]
2026-10-09 00:20:01,235 INFO 待ち受け 127.0.0.1:4536 [sub]
```

各行の見方:

- 1行目：バージョンと、接続先の rigctld です。
- 2行目以降：待ち受けているポートと、そのモードです。`--listen` を指定したときは、指定したものが表示されます。

つなぎ方を確かめるには、別のコンソールで rigctl を使います:

```
rigctl -m 2 -r 127.0.0.1:4535
f
```

4535（main）なら MAIN の周波数、4536（sub）なら SUB の周波数が返ります。WSJT-X を接続すると、ログに `[main:4535] 接続 127.0.0.1:...` のように記録されます。

※ rigctl の対話モードから `\send_raw` を送っても rigctld に届きません。確認には `f` `m` などを使ってください。

うまくいかないとき:

- `ポート ... を開けません ... 終了します`：そのポートを別のプログラムが使っています（ラッパーを二重に起動していないか確認してください）。ポートは `--listen` で変更できます。
- `[main:4535] ...: rigctld に接続できないため切断`：rigctld が起動していないか、`--rigctld` の接続先が合っていません。rigctld を起動してから、WSJT-X で接続し直してください。
- `制御用接続の応答がずれているため接続し直します`（WARNING）：ラッパー自身の rigctld 接続で、応答の対応がずれたため接続し直しました。自動で回復するので、たまに出る程度なら問題ありません。

### 常駐起動方法

`start_ftx1_rigwrap.vbs` をダブルクリックします。必要に応じて、オプションはvbs内の`EXTRA_OPTS`で指定します（空なら既定値）。

ログオン時に自動起動するには、`start_ftx1_rigwrap.vbs` のショートカットを作り、スタートアップフォルダ（`Win+R` → `shell:startup`）に置きます。

`ftx1_rigwrap.py` と `start_ftx1_rigwrap.vbs` は同じフォルダに置いてください。

### 停止方法

タスクマネージャーで該当の `pythonw.exe` を終了します（ほかにも `pythonw.exe` が動いているときは、「詳細」タブの列見出しを右クリックして「コマンドライン」列を表示し、`ftx1_rigwrap.py` のものを見分けてください）。停止すると WSJT-X の CAT 接続が切れます。ラッパーを起動し直したあとは、WSJT-X で接続し直してください。

### WSJT-X の設定

| 項目                                                 | WSJT-X #1                   | WSJT-X #2                  |
| ---------------------------------------------------- | --------------------------- | -------------------------- |
| 担当                                                 | MAIN                        | SUB                        |
| 起動                                                 | `wsjtx.exe --rig-name=MAIN` | `wsjtx.exe --rig-name=SUB` |
| Rig                                                  | Hamlib NET rigctl           | 同左                       |
| Network Server                                       | 127.0.0.1:4535              | 127.0.0.1:4536             |
| PTT Method                                           | CAT                         | CAT                        |
| Mode                                                 | Data/Pkt                    | Data/Pkt                   |
| Split Operation                                      | None または Fake It         | None または Fake It        |
| 音声入力（ftx1_audio_swap fixed と組み合わせるとき） | Mono（＝LEFT）              | Right（＝RIGHT）           |

- `--rig-name` を付けると、WSJT-X の設定が名前ごとに別々に保存されます（2つ同時に起動するときに必要です）。
- **Split Operation を Rig にしないでください。** ラッパーはスプリット ON（`S 1`）を拒否します。FTX-1 はスプリットの送信側にもう一方のバンドを使うため、デュアル受信と衝突するからです。
- **送信（PTT）は、制御先が操作バンドのときだけ有効です。** 操作バンドでない側の WSJT-X は、送信を指示しても無線機は送信しません（WSJT-X は送信中のつもりになります）。操作バンドを入れ替えたら、送信する WSJT-X の Enable Tx も切り替えてください。
- トランスバータを使うときの周波数オフセットは、WSJT-X ごとに、担当バンドに合わせて設定します。担当が固定されるので、操作バンドを替えても表示はずれません。

## オプション

| オプション  | 既定値                                      | 内容                                                                                               |
| ----------- | ------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| `--rigctld` | 127.0.0.1:4534                              | rigctld の接続先（HOST:PORT。PORT だけでも指定できます）                                           |
| `--listen`  | 4535:main と 4536:sub                       | 待ち受けポートとモード（PORT:MODE。MODE は main / sub / follow / opposite。複数指定できます）      |
| `--bind`    | 127.0.0.1                                   | 待ち受けアドレス                                                                                   |
| `--log`     | ラッパーと同じフォルダの `ftx1_rigwrap.log` | ログファイルのパス。書き込めないときは `%LOCALAPPDATA%\ftx1_rigwrap\ftx1_rigwrap.log` に出力します |
| `--debug`   | -                                           | 受信したコマンドもすべてログに出す（確認用。ポーリングも記録されるので、ログが大きくなります）     |

指定例（vbs の `EXTRA_OPTS` に書く形）:

```
--listen 4535:main --listen 4536:sub --debug
```

## このツールの動作の詳細説明

- クライアント1接続につき、rigctld へ1接続します。routed は最初に `\set_vfo_opt 1`（その接続だけ VFO を明示）にします。rigctld の応答は、そのままクライアントへ中継します。ほかのクライアントには影響しません。
- ラッパー自身の問い合わせや補正は、全クライアントで共有する制御用の接続1本で行います。クライアントの応答には混ざりません。
- 操作バンドは `VS;` で取得します（0.5秒だけ保持。`F` `M` `T` の前は毎回取得）。
- **メモリーチャンネルなどのとき（`F` / `M`）**：制御先が VFO でない（メモリーチャンネル、MEM TUNE、PMS、EMG）とき、次のように扱います。
  - `F`：今の周波数との差が1kHz未満なら何もしません（WSJT-X の送り直しで、メモリーが解除されないようにするためです）。それ以外は VFO に戻してから周波数を設定します。VFO に戻したときは、メモリーのモードを引き継ぎます（W-FM は CAT で設定できないので引き継ぎません）。
  - `M`：無線機には送らず、モードを最大10秒間保留します（成功を返します）。その間に `F` で VFO に戻したときに、保留したモードを設定します。期限が切れたときは、メモリーのモードを引き継ぎます。
- 制御先が操作バンドでない側のとき、VFO に戻すには操作バンドを一瞬（約0.1秒）入れ替えて元に戻します（FTX-1 は、操作バンドでない側への VM コマンドを無視するためです）。この間、表示が切り替わります。ftx1_audio_swap がその瞬間を読むと、音声が一度切り替わる可能性があります。送信中は入れ替えず、`F` / `M` を中止して RPRT -9（無線機が拒否）を返します。
- **ナロー補正**：`M` で PKTUSB / PKTLSB（DATA-U / DATA-L）にした後と、`F` で周波数を変えた後に、DATA-U / DATA-L でナローが ON なら OFF に戻します（FM のナローなどはそのままです）。バンドを変えると、そのバンドに記憶されたナロー状態が呼び出されることがあるためです。
- **`\chk_vfo`**：rigctld は「直前にコマンドを処理した別の接続」の値を返すため、ラッパーが答えます（routed は常に 0、follow はクライアント自身が `\set_vfo_opt 1` を送っていれば 1）。あわせて rigctld にも `\chk_vfo` を実行させます（rigctld が `\dump_state` の応答を最後まで出すために必要です）。
- 未知のコマンドは、手を加えずに中継します。
- 想定外のエラーが起きたときは、その接続だけを閉じてログに記録します。ラッパー全体は止まりません。

## ログ

- ログ：`ftx1_rigwrap.log`（ラッパーと同じフォルダ。1MB×4世代でローテーション）
- 記録するもの：起動・待ち受け、接続と切断、VFO に戻したとき、保留したモード、ナロー補正をしたとき、無視・拒否したコマンド、エラー。ポーリングは記録しません（`--debug` で記録できます）。

## テスト

`tests` フォルダに、簡易エミュレータ（`mock_rigctld.py`）を使ったテストがあります。実機は不要です。ソースを改変したときなどに使います（配布 zip には含まれていません。GitHub のリポジトリの `tests` フォルダにあります）:

```
python tests\test_rigwrap.py
```

最後に `FAILS: 0` と表示されれば、すべての項目が通っています。

## 変更履歴

- Ver.2.0 既定の待ち受けを `4535:main` / `4536:sub` に変更（WSJT-X #1 を MAIN、#2 を SUB の担当に固定）。`follow` / `opposite` も指定できる。READMEを拡充
- Ver.1.9（2026-10-02）`\chk_vfo` を受けたとき、rigctld にも `\chk_vfo` を実行させるようにした（rigctld 起動後に誰も実行していないと、WSJT-X が接続できないため）
- Ver.1.8（2026-10-02）`\chk_vfo` をラッパーが答えるようにした。制御用接続で応答のずれを検出したら接続し直す
- Ver.1.7（2026-10-01）`F` の後、DATA-U / DATA-L でナローが ON なら OFF に戻すようにした
- Ver.1.6（2026-10-01）想定外のエラーの内容をログに出すようにした
- Ver.1.5（2026-10-01）メモリー中の `M` を保留し、`F` で VFO に戻すときに設定するようにした
- Ver.1.4（2026-10-01）バンド変更時の CAT のやりとりを減らした
- Ver.1.3（2026-10-01）メモリー中は、今の周波数との差が1kHz未満の `F` を無視するようにした
- Ver.1.2（2026-10-01）VFO に戻すのは `F` で周波数を変えるときだけにし、メモリーのモードを引き継ぐようにした
- Ver.1.1（2026-10-01）操作バンドでない側は、操作バンドを一時的に入れ替えて VFO に戻すようにした
- Ver.1.0（2026-10-01）初版
